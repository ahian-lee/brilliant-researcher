# 项目协作工作台

[English](research-workbench.md) · [中文首页](../README_CN.md) · [架构](architecture_CN.md)

按 [安装说明](../README_CN.md)，用 `npm run connect` 引导连接、`npm run doctor` 做无模型诊断、`npm start -- --with-runtime` 联合启动后，打开 [本机工作台](http://127.0.0.1:8791/)。选择一个项目后，概览、流程与技能、图表和右侧项目对话都围绕同一个项目工作。默认执行后台使用 DSH 与 Codex 原生接口，需要另行安装和配置这些 agent，并保持原生后台运行；无需 Paseo。

Windows 上通过 npm 安装的 agent，应选择 `node.exe` 并填写其 CLI JavaScript 入口；`.cmd` 或 `.bat` 包装器不能作为原生可执行文件启动。DSH 与 Codex 都支持这种方式。诊断会核对端口和配置归属，不调用模型，也不代表提供方鉴权或推理已验证。

使用顶部栏的 **EN / 中文** 按钮切换英文或中文界面。默认使用英文，浏览器会保存你的选择。新建项目弹窗中也可切换，包含已填写草稿的状态。切换保留草稿且不发送 agent 命令；项目目标、对话、agent 输出、成果和上游技能原文按原语言保留，不会自动翻译。

## 先确定目标和范围

新建项目时写清要完成什么、可以使用哪些目录和资源，以及费用、联网或项目外操作的限制。默认按项目范围自主执行，普通读写、测试和返修不逐项打断；涉及范围、费用、资源或方向选择时再请你决定。需要逐项权限复核时，也可以选择该模式。

可以从自由协作、ARIS 单项任务或完整研究流程开始，三种模式都提供“自动执行与 Codex 审核”。单项任务采用选中的技能，完整研究流程需要明确选择。工作台管理的协作中，ARIS 提供所选研究指令，BRI 负责执行、审核和返修，替代技能内部另开审核者与重复返修循环。选择单项技能不会隐式选择整个 pipeline。关闭自动协作后，按选定指令直接执行，不自动获得独立验收；此选项与历史 Direct 集成不同。模型和思考档位来自执行端；配置值与实际运行值分别显示，模型出现在列表中不代表已经实测可用。

## 设置预算

新建时可选填预算，已有项目可在概览的“项目预算”中修改：

| 设置 | 含义 |
| --- | --- |
| 执行时间 | 每个协作轮次的分钟数，默认 6 小时 |
| 返修次数 | 审核后最多返修轮数，默认 3 次 |
| tokens / USD | 本轮累计上限，包括已登记子任务 |
| 同时运行的 agent | 项目活动 agent 上限，包含父会话和子会话 |
| 子会话数 | 整个轮次累计创建上限，不是每个动作重新获得额度 |

空白清除显式设置。tokens 或费用为零表示禁止后续对应模型消耗；子会话为零禁止委派；返修为零禁止返修。时间必须为正，并发至少为一。没有编辑的数值保持原样。保存是对后续工作的预算授权，不扩大当前轮次已批准上限，也不自动重启已耗尽轮次。概览分别显示当前轮次上限与保存的项目默认值。继续新迭代时使用新预算，保留此前轮次用量与成果。

本轮用量来自后台按原生会话增量汇总，父子会话贡献由后台处理。会话卡片显示各自用量，不要再把它们加到本轮总计。缺失 tokens 或费用表示**未报告**，不等于零；不完整报告仍显示不完整。设置了上限但缺少计量、无法确认剩余额度时，系统停止新增受管理动作并显示原因。检查发生在派发和状态观测边界；提供方计量延迟和正在运行的回合可能超过已报告阈值，因此 BRI 预算不等同于提供方预付费硬额度。直接发送也使用预算范围，但不会因此获得自动审核和返修。

从 v0.2.1 起，复用 DSH 会话可以在会话历史 token 总用量仍未知时，单独提供新轮次的精确 token 增量。前提是历史未计量事件身份集合不变、已报告 token 累计值不倒退。新增缺项、计量覆盖变化或倒退会使该轮 token 计量不再可信，并在其 token 上限下持续阻断后续原生派发；后续报告不会静默清除这一阻断。历史缺失用量不会记作零，也不会改写为完整。费用仍需自身报告支持，否则本轮 USD 增量保持未知。

## 执行、审核和中途调整

自动协作按 DSH 执行 → 独立 Codex 审核 → 按意见自动返修推进。交付或消息显示“已接收”只说明请求送达，成果是否通过要看独立审核结论。网页关闭后，后台仍可继续推进。

DSH 是执行工具名，不能据此确定模型家族。ARIS 阶段只记录 `dsh` 或 `dsh-pi` 时，验收使用原生会话实际报告的模型，并保留原始工具标签。缺少实际报告时不能用配置模型代替；未知家族仍不判定独立性，同家族审核仍为暂定，也不能借此覆盖已记录的其他模型。

右侧“项目对话”是统一入口，可以查看动态、发送要求或切到“待处理”。在绑定的执行或审核会话中发送项目调整，会同步两方；后台停止旧回合，两方确认新要求后继续，不采纳旧方向的结果。Enter 发送，Shift+Enter 换行，中文输入法确认选词不会发送。

登记的子任务使用原生会话，显示父会话、任务、状态和可用计量。BRI 限制创建与并发，并在转交成果给审核者前检查子会话。暂停或调整方向会撤销旧动作的委派权限并请求打断子会话；不能确认停止时等待，不继续派发，状态保持可见。请求送达不代表所有子会话已停止。

需要人工判断时，“卡住的地方”和“待你决定”给出原因与对应入口；自动权限审核显示为系统活动，不计入催你决定的人工事项。预算耗尽、执行者明确报告受阻、传输错误和自动审核分别展示；人工队列为空不代表运行正常。具体题目、选项、操作内容和可用回答方式都在同一个“待处理”页签。请使用对应问题的提交按钮答复，处理后可查看答复记录。需要补充项目要求时仍使用普通对话，无需转发审核意见或另开批准窗口。

恢复次数有限。确认空闲却没有有效交付的会话，最多两次请求诊断并继续；最终回执格式不符另有最多两次仅重述格式的机会，不重复实施。发送结果不明时保留观察，不盲目重发。真实受阻会携具体原因停止并保留成果；持续失败转为可见的待处理状态，不无限重试。

延迟的原生历史读取保留较新的控制器范围、撤销与预算状态，即使尚无首次快照。受管理发送在原生提交前失败时，明确返回拒绝及原因；如果请求可能已经提交而回执丢失，结果保持未知，不重发请求。

受管理的新任务 prompt 发送前，最新 assistant 调用报告超过 200,000 `totalTokens`、且尚未被后续原生摘要覆盖时，BRI 可对空闲 DSH 会话执行原生 `compact`，保留会话身份与 journal。需要时可在 `var/native-runtime.local.json` 中用 `dsh.contextCompactionThresholdTokens` 设置正数 token 阈值。压缩调用已配置模型，可能产生费用；摘要用量纳入用量账本，失败且无摘要时仍保留未计量。维护后、任务 prompt 前会再次检查范围与预算。300 秒等待与维护状态处理已有软件检查。一次真实会话在 146 秒完成原生压缩，但旧的 120 秒等待在任务提交前拒绝了发送；恢复时保留该拒绝记录，沿原会话使用已完成的原生摘要继续。

模型与思考档位在确认空闲后可调整。执行、审计规划或审核正在进行时，先暂停协作再修改。

## 继续迭代或重做

概览的“继续迭代 / 重做”和流程阶段的“从此阶段重做”都打开现有项目对话，并默认勾选“Codex 先审计并提出计划”。可以直接发送预填的继续迭代意图，也可以补充哪里需要改；无需自己先写完整方案。

暂停、故障或预算耗尽后继续时，复用原执行与审核会话开启新轮。前轮保留自己的时间、用量和回执，新轮使用项目已保存的预算并重新计时。发送结果仍不明确时，需要先确认原请求状态，不能用新轮绕过。

执行交付新 ARIS 轮次后，独立验收与当前进度摘要关联该轮。启动时的后续记录用于未交付新原生轮次的情况，不能替代已交付轮次，也不能将旧轮验收当作新结果；只有实际交付的阶段获得验收。

Codex 先检查已有成果，再给出审计结论、改进建议、执行步骤和验收口径。这些内容直接显示在概览。范围内的计划自动交给 DSH 执行，再由 Codex 独立审核和按需返修；只有范围、费用或方向需要选择时才等待你的答复。

已经完成的协作轮次收到新任务时，也默认先审计规划。若任务已经明确，可以取消勾选，直接按指定任务执行，完成后仍进入独立审核。重做范围可以选择从头重做已启用流程、从某阶段往后重做或只重做某阶段；选择范围本身不会启动任务，发送才开始。缺少绑定的 Codex 审核者时，对话提供连接空闲审核者的入口并保留请求和范围；仅连接审核者不会发起模型回合。方向同步显示绑定执行者与审核者各自确认，不假定所有子会话都已确认。

审计认为无需新增工作时，计划返回 `no_change`，协作状态为 `audited`（审计完成 · 无需新增执行）。这表示本次只完成了审计，没有派发新的 DSH 执行，也没有产生一次新的科学验收。`accepted` 表示对应成果通过独立审核；阶段 `done` 或执行结束仍不能当成 `accepted`。

## 查看进展、历史和成果

概览首先展示结论、目标差距和当前步骤，同时保留会影响结论的证据限制；长计划与技术细节可以展开。执行成果及匹配轮次的审核结果放在摘要旁，通过受限于项目的成果链接访问。受阻交付展示真实原因，旧方向成果不会被标为新方向已通过。进度条统计实际阶段验收；审计规划期间显示尚未开始执行，受影响阶段在执行后重新推进。以前通过的阶段不会冒充本轮通过。

“流程与技能”展开当前轮次，旧轮次放在“历史轮次”中，原产物和验收记录保留。“图表”汇集项目中实际存在的图片和 PDF；没有用途清单的图表显示为未分类。

“导出成果”下载 ZIP，包含支持的文档、图表、数据、代码和进展文件，具体打包范围见包内 `EXPORT_README.md`。凭据、会话原始日志、依赖和缓存不进入成果包；超限或打包出错时会明确提示。

“标记已完成”把项目收进左侧“已完成”列表，可继续查看、导出或恢复。它是收纳标记，不等于科学验收，也不会停止正在运行的会话。接收后续任务时，已收纳项目可以重新进入进行中。

## 验证范围

v0.2.1 在一个已有 Windows 研究项目上复用原生会话实测恢复：Codex 审计旧成果，DSH 交付修复，Codex 退回三项报告解释错误，返修后通过第二次独立审核。轮次之间发生过提交前的压缩超时，完成后台恢复后继续，原拒绝记录保留。实际交付的 ARIS 轮次与当前进度最终均为 3/3 已验收；旧消息与历史轮次保留，选定测量和检查没有重新打开封存数据。这是一个代表性的研究阶段恢复场景，整体研究目标仍待完成。

v0.2.0 已在 Windows 完成代表性实跑：DSH、Codex 子会话交付真实文件，独立审核拒绝注入的计数器故障，DSH 自动返修。通过 Enter 发送的新方向同步给双方，最终组件通过 6 项测试和独立浏览器验证（0 → 2 → 4 → 重置为 0）。原生问题答复、实际 SVG 预览、匹配的审核结果、阶段进度、ZIP 导出和项目收纳已通过真实工作台/API 验证。预算停止与重启保留会话身份另有实际验证；停止的轮次保留记录，未记为验收通过。

[tests](../tests) 的软件检查覆盖原生接口、有限恢复、项目隔离、预算、迭代、导出及双语界面。[nativeCollaborationRecovery.ts](../tests/nativeCollaborationRecovery.ts) 联合检查核心与后台恢复链，[nativeRestartRecovery.ts](../tests/nativeRestartRecovery.ts) 覆盖协议已发出、状态尚未保存时崩溃且不得重发的边界，[dashboardWorkbenchUx.mjs](../tests/dashboardWorkbenchUx.mjs) 在不调用模型的情况下检查界面状态与未知用量。

隔离测试、浏览器预览、提供方发现和构建成功不能证明认证、推理、完整 ARIS 流程执行或科学正确性，不声称所有技能和模型已验证。私人研究材料与原始会话不随公共源码发布。

部署与数据边界见 [架构](architecture_CN.md) 和 [SECURITY.md](../SECURITY.md)：面向可信机器的 localhost；full-access 不扩大授权；模型调用可能产生费用，并可能向配置的模型提供方发送项目内容。


### 如何读实时执行反馈

概览和项目对话共用原生会话状态：当前工具或上下文压缩、实际命令或文件、最近文字反馈，以及距最后一次真实活动的时间。另一处时间标明看板何时成功读取后台；读到状态不等于模型正在取得进展。

超过 90 秒没有新输出时，页面会提示观察不到新进展，不会据此判定进程停止或自动重启。刷新状态只读状态，不会再次提交任务。状态读取在 20 秒超时后保留上次记录和草稿；任务提交不使用这个读取超时。

服务商额度或鉴权错误、协作故障和会话错误会显示原始原因，并提供回到对应会话的入口。服务商额度限制与项目预算分别说明。执行端说“等待输入”但尚未返回原问题时，页面显示“等待原因需要核实”，不计作用户能够回答的问题；真正的问题会打开原题与答复表单。暂停和改方向沿用已有协作接口。阅读旧消息时，新输出不再强行滚动，点击新消息按钮即可回到最新位置。

项目设置、预算和导出集中折叠，优先保留执行反馈的可见空间。中英文界面使用同一套状态规则。这些界面调整不改变研究数据、凭据、权限或原有会话。
