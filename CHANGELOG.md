# Changelog / 更新记录

## 0.2.1 — 2026-10-20

- Pipeline continuation records acceptance on the new ARIS run identified by the execution receipt and publishes that same run as current progress. The startup follow-up remains a fallback when no new native run is delivered; historical runs and undelivered phases are preserved. / 流程迭代将验收写回执行回执指明的新 ARIS 轮次，进度摘要使用同一轮；未交付新原生轮次时沿用启动记录，保留历史轮次与未交付阶段。
- ARIS phase acceptance resolves a recorded DSH agent label using the model actually reported by its native session. The original agent declaration and older runs remain intact; missing model evidence stays unclassified and same-family review stays provisional. / ARIS 阶段验收用原生会话实际报告的模型补全 DSH 工具标签，保留原始执行工具与旧轮记录；缺少模型证据仍不判定独立性，同家族审核仍为暂定。
- Reused DSH sessions retain unknown lifetime usage when historical events lack tokens. Round token deltas are exact only while the same historical unmetered event identities remain and reported totals do not regress; new gaps or regression persistently block further native dispatch under that round's token cap. Token coverage does not establish USD coverage. / 复用 DSH 会话时，历史事件缺少 tokens 的会话总用量仍为未知。仅在历史未计量事件身份集合不变、已报告累计值不倒退时，本轮 token 增量才可精确计算；新增缺项或倒退会在该轮 token 上限下持续阻断后续原生派发。token 计量完整不代表费用已知。
- An in-flight native history read cannot replace newer controller scope, revocation or budget state, including before the first snapshot is available. / 尚未完成的原生历史读取不能覆盖较新的控制器范围、撤销或预算状态，包括尚无首次快照时。
- A managed send failing before native submission returns an explicit rejection with its reason. A lost acknowledgement after submission remains unknown and is not replayed. / 受管理发送在原生提交前失败时明确返回拒绝及原因；提交后丢失回执仍保留未知，不重发。
- Continuing a paused or faulted collaboration starts a new round on the original conversations, preserving old usage, timestamps and receipts. Days offline no longer spend the next round's duration before it starts; unresolved delivery still prevents replacement dispatch. / 暂停或故障后继续协作时，复用原会话开启新轮，保留旧用量、时间和回执；离线数天不会提前耗尽新轮时间，发送结果不明仍阻止替换派发。
- Codex launches with the default app-server stdio transport. A removed Desktop-managed executable can resolve to a remaining versioned installation, without downgrading to a leftover unversioned CLI; existing explicit and custom selections are retained. / Codex 使用 app-server 默认 stdio 传输；Desktop 升级移除已配置程序后，查找仍存在的版本目录，不降级到遗留的非版本 CLI，保留现存显式路径和自定义选择。
- Before a new managed prompt, an idle DSH session compacts when its latest assistant call reports more than 200,000 total tokens and no later native summary covers it. Native session identity and journal are retained. Compaction uses the configured model, may incur charges, and its reported usage is counted; failed compaction without a summary remains unmetered. Scope and budget are checked again before the task prompt. Software checks cover the implementation; live long-session effectiveness is not yet established. / 受管理的新任务 prompt 发送前，空闲 DSH 会话在最新 assistant 调用报告超过 200,000 total tokens、且未被后续原生摘要覆盖时压缩上下文，保留原生会话身份与 journal。压缩调用已配置模型，可能付费，报告用量纳入计量；失败且无摘要时保持未计量。任务 prompt 前再次检查范围与预算。实现已由软件检查覆盖，长会话真实效果尚待验证。
- Workbench regression checks cover these budget, history-read and dispatch boundaries. This patch does not establish acceptance of an ongoing research iteration or validation of every ARIS workflow. / 工作台回归检查覆盖上述预算、历史读取和派发边界。本补丁不代表进行中的科研迭代已通过验收，也不代表全部 ARIS 流程已验证。

## 0.2.0 — 2026-10-15

- Native parent/child orchestration records ownership and action/revision, bounds child creation and concurrency, and waits for child shutdown before review or a new direction. / 原生父子协调记录归属及动作/修订，限制子会话与并发，在审核或新方向前确认子会话停止。
- Finite continuation and format-only recovery preserve artifacts and surface real blocked reasons; uncertain sends are not replayed. Project scheduling uses independent bounded ticks and backoff. / 有限继续执行和仅重述格式的恢复保留成果，展示真实受阻原因，不重放结果不明的发送；项目独立调度并有限退避。
- All free, selected-skill and full-workflow modes offer managed execution → independent Codex review → repair. ARIS research instructions remain selected explicitly; managed orchestration replaces nested reviewer/repair loops. Direct execution remains available without automatic independent acceptance. / 自由、单项技能及完整流程均可选执行→独立 Codex 审核→返修；显式选择 ARIS 研究指令，宿主协调替代内部审核/返修循环；直接执行不自动获得独立验收。
- Project budget editing and per-round approved caps cover duration, repairs, tokens, USD, concurrency and total child sessions. Native usage remains unknown when unreported, rather than zero. / 项目预算与轮次上限覆盖时间、返修、tokens、美元、并发和累计子会话；未报告的原生用量保留未知，不记作零。
- EN/中文 overview separates human decisions from automatic permission review, puts artifacts and matching review beside the summary, folds long plans, and preserves drafts and redo scope. / 双语概览区分人工决定与自动权限审核，摘要旁展示成果及匹配审核，折叠长计划，保留草稿与重做范围。
- Interactive `connect`, no-model `doctor`, combined `start --with-runtime`, and source-based rebuild/upgrade instructions preserve existing local configuration and project registration. / 交互连接、不调用模型的诊断、联合启动和源码重建升级保留已有本机配置与项目注册。
- Native metadata replacement tolerates brief Windows sharing locks; persistent save failures are visible and prevent unsaved dispatch. Restart recovery reacquires the original native owner without replaying uncertain sends. Proven empty Codex threads can recover while retaining the BRI session binding. / 原生元数据保存容忍 Windows 短暂共享锁，持续失败明确显示并阻止未保存的派发；重启时恢复原生 owner，不重放结果不明的发送；已证明为空的 Codex 线程可恢复并保留 BRI 会话绑定。
- Windows agent launches restore a missing `PATHEXT`; connection setup supports Node CLI entries for either agent. Streaming replies are labelled as generation using actual message progress. / Windows 启动补齐缺失的 `PATHEXT`，连接向导支持两种 agent 的 Node CLI 入口；流式回复按真实消息进展显示“正在生成回复”。
- Project summaries reuse shared report reads within each call and avoid a duplicate overview scan; subsequent requests still read current files with the same containment checks. / 项目摘要在单次调用内复用共享报告，避免概览重复扫描；后续请求仍读取最新文件并保留路径安全检查。

**Representative live acceptance passed.** Native DSH execution and two actual DSH/Codex child sessions, independent rejection and automatic repair, in-flight direction synchronization, native question answering, six passing component tests, browser behavior, figure preview, result export and budget stops were exercised. This does not validate every ARIS skill, model or scientific workflow. Boundaries are in [English README](README.md#validation-status) and [中文 README](README_CN.md#已验证范围).

**代表性真实验收已通过。** 已实跑 DSH 原生执行、DSH/Codex 两个真实子会话、独立拒绝与自动返修、中途方向同步、原生问答、组件 6 项测试、浏览器行为、图表预览、成果导出和预算停止。这不代表全部 ARIS 技能、模型和科研流程已验证。
